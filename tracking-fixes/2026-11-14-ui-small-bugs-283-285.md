# Three small UI bugs from the README screenshot pass, 2026-11-14

**Linear:** NET-283, NET-284, NET-285
**Branch:** `fix/ui-small-bugs-net283-285`
**Status:** done. PR #290 merged (`261c79fb`); deployed to the G11 at `f10eee24` (`deploy-triage-fixes-3-2026-11-14.sh`: the full-stop plan line is in the built app). The 1440 px table fit is checked by `e2e/visual/table-fit.visual.ts`, not on the box.

## Problems and root causes

- **NET-283, Packets.** With "All traffic", the plan line ended "…with no filter, so every packet:" and
  nothing followed. `QuestionBuilder.svelte` used a colon in both cases, but the `<code>` filter after
  it only renders when there is a filter.
- **NET-284, DHCP timeline at 1440 px.**
  - The link and the hint after it ran together ("packetsShows"). Svelte trims the leading space inside
    `<span> Shows…`.
  - The Messages column was cut off. `system.css` makes every table cell `nowrap`, so the "What NetTap
    saw" sentence plus its hint made that column 727 px wide, and the table came out 1638 px in a
    1086 px card. `.tbl-wrap` scrolls, but overlay scrollbars hide it, so it looked clipped.
- **NET-285, Changelog at 1440 px.** The same `nowrap` inheritance: ten columns came to 1154 px
  against 1086 px. `.what` already had `overflow-wrap: anywhere` but could never wrap.

## Fix

- NET-283: the no-filter case ends in a full stop.
- NET-284: the space sits between `</a>` and `<span>`. The sentence cell (`.saw`, `min-width: 12rem`)
  and the Messages cell wrap, using the Packet analysis `.what` pattern.
- NET-285: `.what` wraps down to 10rem, and the Events table uses one step tighter cell padding
  (`var(--sp-2)`), as the packet drawer's table does. Wrapping alone couldn't recover the last 68 px
  without breaking names and MACs mid-word.
- Replaced lines are kept as OLD CODE comments.

## Tests

## Lessons

`system.css` makes table cells `nowrap`, so any long text cell needs its own `white-space: normal`
and a `min-width`, or the table grows past its card. `.tbl-wrap` hides the overflow behind an
overlay scrollbar, so it reads as clipping, not scrolling.
